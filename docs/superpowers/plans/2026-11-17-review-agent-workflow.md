# 路线审核父子 Agent 框架实施计划

按阶段执行本计划。框架使用现有 Python 异步运行方式、模型客户端和审核工具。业务设计参考 [审核工具和系统 Prompt 草案](../../chat-react-system-prompts.md)。

## 范围和文件

- `agent/chat/review_workflow.py` 管理单轮请求、版本和最终提交。
- `agent/chat/review_parent.py` 复用现有模型调用适配，负责选择工具、生成任务以及修订任务。
- `agent/chat/review_scheduler.py` 从第二阶段开始实现 DAG 校验和执行，第三阶段加入局部失效。
- `tools/review.py` 提供审核工具，`service/travel/review.py` 承担最终版本校验和保存。
- 先做可独立调用的框架入口。用注入的执行函数模拟路线审核、地点候选和行程操作。专业 Agent 的 Prompt、模型与具体业务执行留给后续。

## 阶段一 · 固定外层 Workflow

- [ ] 定义 `run_review_turn(request, context) -> ReviewTurnResult`。请求携带用户消息，运行时上下文绑定行程、版本、写入权限和本轮预算。结果状态为回答、提案、已保存、需澄清、冲突或失败。
- [ ] 外层固定经过读取已保存快照、Parent 循环、校验结果、按授权提交、返回结果。第一版以已保存版本为基线，审核页有未保存草稿时交由调用方处理该差异。
- [ ] Parent 按需调用只读审核工具，根据观察继续查询或返回结构化意图。编辑意图输出 `operations`，整路线优化输出独立的优化意图。直接答复、提案和澄清均可提前结束。
- [ ] Workflow 持有写工具，执行权限、阶段与版本检查，批量编辑只提交一次。版本冲突要求刷新，写入结果未知时先核实当前状态。
- [ ] 验收用例覆盖只读问答、提案、成功提交、越权请求、旧版本和超时。验证只读角色的工具调用无法触发保存。

## 阶段二 · 动态子任务 DAG

- [ ] Parent 输出 `TaskSpec(id, kind, input, depends_on)` 列表。任务类型预留 `audit_route`、`search_places`、`build_edits`。通过 `handlers[kind](task, dependency_results, context)` 注入执行器，框架验收使用固定结果。
- [ ] Scheduler 在执行前拒绝重复 ID、未知类型、缺失依赖、环及超出任务预算的计划。只并行启动依赖全部成功的任务，设置并发上限，独立分支失败时可继续，依赖失败的下游标记为阻塞。
- [ ] 任务结果记录状态、结构化产物、行程版本和实际依赖结果。外层 Workflow 收到最终操作提案后继续使用阶段一的保存路径。任务处理器只持有只读工具。
- [ ] 验收用例使用两个独立任务和一个汇总任务。检查两个读任务并发、汇总等待两份结果，以及非法 DAG 在任何工具调用之前被拒绝。

## 阶段三 · 执行中重新规划

- [ ] 允许任务返回带原因和证据的 `needs_replan` 结果。Scheduler 停止派发依赖该结果的任务，外层将原 DAG、已完成结果和失败原因交回 Parent。
- [ ] Parent 提供修订后的完整 DAG。Scheduler 重验整张图，并比较任务定义、行程版本与依赖结果。明确重试的任务、定义改变的任务及其传递下游需要重跑。独立且输入一致的成功结果复用。
- [ ] 重规划沿用本轮的步数、工具调用和时间预算。候选不可用的验收场景由模拟执行器提供。预算耗尽时返回已确认结果和阻塞原因。提交前执行现有版本校验。
- [ ] 验收用例模拟地点关闭，验证替代搜索和下游提案重跑，独立的车站检查只执行一次，旧提案无法进入保存。

建议按阶段独立提交。每阶段先使用模拟模型响应和任务执行器验收，再决定何时挂到审核页聊天入口。
