# 前端交互与规划流程修改计划

> 执行状态：Task 1–4 已实施并验证，Task 5 已按用户要求排除。详细结果见同目录 `2026-10-29-frontend-ux-progress.md`。

**Goal:** 让用户在每个步骤都知道当前状态、无法继续的原因、应该修改的位置，并能从失败中恢复。

**Architecture:** 保留现有 React 页面与后端规划流程。先对齐前后端校验和保存语义，再添加可定位的问题清单、失败恢复与状态反馈，最后调整信息布局；不引入新的 UI 框架或全局状态库。

**Tech Stack:** React 19、React Router、Vite、FastAPI、现有 Python unittest。

**依据：** 用户提出的 UI 不合理、下一步不可点击且原因不明；以下清单记录修复前的源码证据，代码行号可能随实施发生变化。

## 三、验证与交付标准

1. 前端目前没有 test 脚本或交互测试框架。先用现有 Python unittest 固定后端关键规则；前端纯校验可使用 Node 自带测试，浏览器交互自动化是否添加 Playwright 在实施时明确，不假装已有测试命令。
2. 每个任务先验证其问题场景，再实现最小修复；布局和文案以浏览器验收为主，不写只检查 CSS 字符串的测试。
3. 构建：在 frontend 运行 `npm run build`；后端针对修改运行 `uv run python -m unittest discover -s tests -p "test_guided*.py" -v`，涉及地图审核时再运行 `uv run python -m unittest discover -s tests -p "test_map_review.py" -v`；最终跑完整 unittest，并区分既有失败。
4. 端到端覆盖：一日游无住宿、多日游有住宿、自驾、酒店与必去项未定位、排除项错误、超预算、地图不可用、模型失败、主请求成功但列表失败、切换行程时旧请求延迟、聊天发送失败、购买金额为空与零元。
5. 完成条件：所有主按钮均能说明禁用原因；所有可阻断问题都有可执行修复路径；加载失败可恢复；已保存结果不误报失败；已有草稿、购买记录和用户输入不因重试或跳转静默丢失。

## 四、建议取舍

- 本计划共 4 个任务：先完成 Task 1–3，再做 Task 4。只改配色与间距无法解决阻断、误报失败和恢复问题。
- 按用户要求移除原 Task 5；问题 16 保留为审查记录，不纳入本轮实施和验收范围。
- 本轮建议保持现有业务规则，尤其不直接解除 high 级审核阻断。若要允许超预算确认，应作为独立产品规则评审并同步修改前后端。
- 暂不重写前端、不换 UI 框架、不加入全局状态库，也不在本计划内实现真实票务购买。
- Task 1–4 已完成：后端全量 171 项、前端单元测试 15 项通过，生产构建成功，核心浏览器交互回归通过。真实地图、模型和数据库联调不在本次验证结果内。
