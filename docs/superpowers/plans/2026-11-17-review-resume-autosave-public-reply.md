# 路线助手断点恢复、自动保存与公开回复实施计划

> 按以下顺序完成各项任务，每项包含独立验收条件。

**目标**：用户选择或回复后从暂停点继续。审核页每 3 秒检查并静默保存有效编辑。Agent 每个修改批次只加载一次最新行程，验收通过后直接写回并刷新页面版本。用户能看到自然语言答复和可操作内容，内部标识与编排细节保留在诊断日志。

**架构**：保留现有审核 Workflow、父子 Agent 和任务 DAG。添加明确的审核断点状态和恢复入口，复用现有数据库行程版本比较与事务写入。由同一个前端写入队列协调页面编辑和 Agent 修改。公开回复在服务端出站时统一生成和校验。

**技术栈**：Python、FastAPI、现有数据库存储层、现有模型客户端和 React。

## 当前行为与设计取舍

- 澄清虽然带回了旧问答，但 `run_review_turn` 每次都会重新跑意图检查。地点和预览动作依赖进程内表，重启后失效。新设计保留现有执行器并显式保存暂停状态。将整条审核流程改造成 LangGraph 的中断节点会涉及更大迁移，首版采用同样的暂停与恢复语义，由现有 Workflow 支持。
- 页面目前通过 `edits` 暂存操作，显式保存后更新 `plan_version`。Agent 用网页传来的操作重建草稿。新设计先通过页面写入队列提交本地有效编辑，再让 Agent 在后端基于最新已保存版本规划和提交。
- 现有 `save_review_changes` 已经在事务中锁行并比较原版本，可以继续作为所有审核写入的最终保护。该提交检查和返回写入结果属于数据库边界，Agent 中途重复读取不参与并发控制。
- 范围限定在路线审核页。已确认路线继续只读，普通聊天的会话与保存行为不在本轮改造范围内。

## 任务一 · 可恢复的审核断点

**涉及文件**：`agent/chat/review_workflow.py`、`review_parent.py`、`review_scheduler.py`、`service/travel/review_interaction.py`；在 `service/storage` 增加审核断点持久化。参考已有规划任务的 checkpoint 存储形式，审核断点按会话和运行隔离。

- [ ] 定义 `ReviewCheckpoint`，持久化会话、行程、暂停时版本、恢复阶段、已识别意图、已完成并仍可复用的任务及结果、待选动作、剩余执行预算和状态。只保存必要且可序列化的数据。
- [ ] 将澄清、候选选择、试算确认做成明确的暂停点。澄清恢复时把答案补入已识别意图，只判断当前缺失项是否解决。候选选择恢复时用已选的候选直接进入后续定位和试算。确认恢复时只校验并应用已展示的提案。
- [ ] 聊天发送与恢复使用同一个审核入口。恢复请求只提交服务端发出的继续凭据及选择或自定义答复，客户端不回传模型状态。断点绑定行程和对话，并验证选项合法性；无效输入应保留断点供用户更正。
- [ ] 地点选择断点声明 `selection_mode`（`single` 或 `multiple`）和允许选择的数量。明确要求选一个时预设单选，要求选多个时预设多选，未指定数量时提供单选与多选切换。单选点击候选即提交，多选勾选完成后集中提交。服务端校验模式、数量、重复项及候选归属，只恢复一次。
- [ ] 多选地点作为同一个请求继续规划。先联合试算路线、排程和审核，全部通过后一次提交。部分地点无法安排时，展示无法安排的地点和原因，让用户确认缩小范围。
- [ ] 通过原子状态变更防止两个请求同时恢复。同一个恢复请求重复到达时，返回处理中或已经完成的结果。提交后的成功记录与行程写入须保证一致，避免响应丢失后第二次应用同一批操作。
- [ ] 恢复时发现版本变化，保留用户已答内容和仍有效的候选。仅重新校验受影响的目标和下游任务。如果用户确认过的预览内容会变，重新展示并征求确认。显式开启的新问题按新一轮处理，历史中的未完成断点可回到原对话继续。
- [ ] 验收：模拟用户选择后，无重新意图识别或重复高德搜索；刷新后恢复原暂停位置；服务重启仍可恢复；无效选项、串会话、重复点击、确认期间版本变更都有明确结果。

## 任务二 · 审核页静默保存与单次快照

**涉及文件**：`frontend/src/ReviewPage.jsx`、`frontend/src/reviewDraft.js`、审核页助手组件、`tools/review.py`、`service/travel/review.py`、`service/storage/planning_jobs.py`。沿用 `review_changes` 的批量写入路径。

- [ ] 审核页每 3 秒检查有效待保存操作。仅有变更时提交，页面保持可操作。同一时刻最多一个写请求。提交时固定本批操作和基准版本，新编辑留在队列。响应后只移除已经确认保存的操作，保留后续编辑并按新版本重新应用。失败时保留草稿，显示简短的状态和重试入口；导航保护以是否仍有未保存操作为准。
- [ ] 页面编辑、立即重算、确认路线和 Agent 写入共用前端写入队列。发送可能修改行程的请求前，先提交当前有效待保存操作并等待正在执行的写入完成。Agent 写入期间用户仍可形成新编辑，但同页后续自动保存等到 Agent 完成。等待用户选择时释放队列，恢复写入前重新同步。
- [ ] 未经用户授权的咨询、推荐和澄清不写行程。明确的添加按钮和「应用」按钮只授权对应提案。Agent 写入前在服务端读取一次最新版本，绑定给工具与试算流程。Agent 针对该快照解析目标并验收，写入同一份通过试算的候选，不让模型提供行程版本。
- [ ] 数据库事务保持版本比较。其他浏览器或请求在 Agent 试算期间写入时，返回冲突并保留本地编辑。仅对能证明确实不相交的编辑执行已有或确定性的重放；已更改同一字段或被删掉的锚点需要重新确认。写入超时导致结果未知时先核实，避免重复提交。
- [ ] 写成功后统一用返回的行程、版本、审核结果更新页面。日程和地图跟随新版本，较早请求返回的地图不得覆盖最新结果。无效表单字段不会自动提交。
- [ ] 已获授权且验收通过的 Agent 修改直接写回同一行程。成功后整页使用服务端返回的新版行程替换原基线，并保留写入期间排队的手动编辑。Agent 已提交的操作不再进入自动保存队列。若期间有别处提交，先校验受影响操作，再对最新版本提交；同一字段有冲突时等待用户决定。
- [ ] 验收：两次定时检查只发一次在途请求；保存期间新增编辑不会丢；Agent 读取到已静默保存后的数据，试算和提交中间不重复调用读取工具；其他标签页改同一字段时无覆盖；无变化和无效状态不提交。

## 任务三 · 专门的公开回复阶段

**涉及文件**：审核 Workflow、交互服务、工具结果的脱敏投影、`ReviewAssistant.jsx` 和运行日志。

- [ ] 补充公共结果投影，只给回复模型传实际完成状态、地点名称、日期、时间、审核问题和用户可选项。保留业务事实，替换错误中拼接的内部标识。用户可见字段和机器动作字段使用不同的接口契约。
- [ ] 增加专用公开回复 Prompt。基于已确认的结果说明完成了什么、遇到什么问题或需要用户决定什么。禁止展示项目 ID、POI ID、Agent 角色、DAG、工具、内部状态、运行版本等信息。模型只负责措辞，不得调用工具、产生授权或改动候选和操作。
- [ ] 在 API 出站前校验所有展示文本字段，包括聊天说明、澄清问题、选项、预览摘要和错误。检测到内部字段名、实际 ID 或编排泄漏，以及回复模型异常、超时时，改用安全模板。模型返回的修改计划、工具调用和原始错误仍可在运行日志查看。
- [ ] 地点卡片和地图继续使用必要的机器标识。前端只渲染公开字段，预览显示人能理解的变更摘要。投影和回复生成使用独立的模型时限，进度显示「正在整理回复」。
- [ ] 验收：用台北车站替换为大安森林公园的错误样本测试所有公开文本。回复要保留第 1 天、原地点、新地点和真实结果，不出现 `place_id`、`item_id`、具体 ID 或子 Agent 等内部术语。结果未保存或写入失败时不得宣称成功。模型超时时安全模板仍可送达。

## 任务四 · 输入框上方的断点选择区

**涉及文件**：`frontend/src/ReviewAssistant.jsx` 及审核页聊天样式，复用地点图片组件和断点回传入口。

- [ ] 参考 Codex，在聊天滚动区和输入框之间放置选择区。面板参与正常布局，不覆盖聊天消息。选项较多或窗口较矮时，选择区自身滚动，聊天区继续独立滚动。
- [ ] 澄清问题提供预设选项和自定义答复。地点支持单选与多选，勾选状态、数量限制和提交按钮在选择区显示。预览确认沿用同一位置。每个对话只显示该对话当前待处理的断点。
- [ ] 回传被接受后移除选择区，只将用户实际选中的内容以简短文本追加到聊天记录。提交期间防止重复操作。提交失败时保留面板和当前勾选，允许重试或更正。刷新和切回历史对话时，只恢复尚未完成的选择区。
- [ ] 验收：桌面和窄屏均能同时看到聊天和选择区。单选只留一个地点名称，多选留下已选地点列表且只发一个请求。已处理的选项不会在刷新后重新出现。

## 端到端验收

用浏览器或前端 HTTP 模拟先移动景点并等到静默保存，再让助手找到替代地点。让助手暂停，刷新并恢复原对话，选择候选，观看进度并验收修改。操作期间由另一个客户端改动行程再单独复测冲突路径。核对数据库写入次数、保存版本、断点状态，确认已有搜索结果复用，地图版本正确，公开回复不暴露内部标识。定时保存使用可控时钟验证，真实模型与高德验证沿用现有内存行程测试边界。
