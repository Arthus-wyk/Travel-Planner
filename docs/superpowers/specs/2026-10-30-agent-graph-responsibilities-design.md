# 行程 Graph 节点职责设计

## 目标与范围

从攻略图片或文字生成可审核的旅行草案。模型负责理解攻略、在高德候选中决定地点、排列每天的中间停留点；程序负责固定锚点、路线方式、费用归集、校验和风险提示。沿用当前 LangGraph、计划数据和审核页，不引入新的报价服务或模拟价格。

## 已选方案

采用现有高德接口逐步补齐真实数据。另一方案是接酒店和票务报价 API，可提供日期相关报价，但当前没有选定服务商或接口权限。高德 POI 的 `biz_ext.cost` 是人均消费，不能充当酒店每晚房价或景点门票。公交、打车费用只在所选路线明确返回有效费用时计入；自驾燃油、停车、酒店房价和门票若没有合适的报价，保持未知。费用合计注明仅含已知项目。

## 节点与契约

1. **输入快照**：读取目的地、日期、人数、预算、旅行节奏、当前选点、已选酒店与往返交通，以及攻略文字或图片。图片先 OCR，原文和识别文字保留供复核。输入变化使旧检查点失效。
2. **攻略提取**：LLM 仅提取原文提到的具体酒店、景点、饭店名称、其他停留点及其备注、日期、时间窗和先后约束。菜名和泛称餐食不是地点。原文没有给出的门票、价格和时长不得猜测。提取结果按稳定地点 ID 保存。
3. **地点搜索与匹配**：程序按原名、地址线索、目的地城市和类别查询高德，并去除明显跨城或类型不符的候选。唯一可靠候选可直接采用；多个候选交 LLM 从候选序号中最终选择，服务端校验其 POI ID、城市、类别及坐标。LLM 不能生成候选外的 POI 或坐标。无有效候选或接口失败时保留未定位状态及原因，不请求用户逐个确认，也不编造位置；需要真实坐标的路线不能标记为已验证。已保存的人工定位不被自动匹配覆盖。
4. **每日排序**：LLM 接收已选且可定位的中间地点、原文约束和固定交通时间，只输出每日有序地点位置；不输出 `unscheduled`、交通方式、时刻或价格。服务端拒绝重复、越界、遗漏、排除点和非法日期，并用具体位置与问题反馈有限重试。根据 2026-10-31 的用户修正，未确定列表仅供用户手动暂存；graph 不填写该列表。未定位或容量冲突记录为生成问题和审核风险。模型修订失败保留上一份完整草稿及风险，不丢失已生成结果。
5. **行程组装与路线**：程序按日期插入家、酒店和已选往返交通锚点。对各相邻市内路段分别查询步行、公交、驾车路线，比较有效路径的预计总耗时，选择最快可行方式；固定城际交通不得改写。记录方式、耗时、距离、费用、来源和失败原因。驾车与打车费用须区分，不能把驾车路径费用当作打车报价。所有方式都失败时标记未验证，审核提示风险。
6. **费用补全**：从高德 POI 的有效人均消费读取饭店费用，从所选公交或打车路径读取有效费用。按人数或车辆单位归集，保存金额、单位、来源与查询状态。酒店每晚房价、景点门票及无法确定的路费标记未知，不计入已知合计；删除生成流程中的模拟价格及默认餐饮或交通额度，防止冒充 API 报价或重复计费。已购金额和用户手填费用仍按现有来源单独保留。
7. **备注和审核**：将攻略提取的地点备注带入行程卡片；正则只用于原文与地点的明确匹配补充。排时后审核总游玩时长、固定交通缓冲、原文硬约束、未安排地点及已知费用与预算。未知价格和未验证路线作为注意事项显示。只有分天或顺序能修复的高风险问题回到每日排序；地图和报价失败不触发模型重试。审核问题不能因自动修订次数耗尽而被隐藏。

## 影响范围与验证

主要涉及 `agent/itinerary.py`、`agent/planning_graph.py`、`service/travel/guide.py`、`service/travel/place_matching.py`、`service/integrations/travel_amap.py`、`service/travel/planning.py`、`service/travel/itinerary_audit.py`、生成检查点和相关测试。审核页沿用现有未确定列表、路线和注意事项，调整费用文案与未知状态。验证覆盖地点重复或遗漏、候选越权、无坐标、路线三选一、固定锚点、费用来源与单位、查价失败、审核反馈和检查点恢复。

## 限制

高德 POI 人均消费并非实时交易报价；酒店每晚房价和门票没有合适接口时始终未知。最快路线依据 API 返回的预计时长，实际交通会变化。地点匹配虽然由 LLM 最终选择，但只能在经过城市和类别校验的真实候选中选择。
