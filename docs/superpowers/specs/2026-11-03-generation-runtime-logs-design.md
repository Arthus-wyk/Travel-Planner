# 行程生成运行日志

用户已确认：将行程生成链路接入现有 `/logs` 页面，按任务编号聚合阶段进度、模型请求与响应、地图调用及异常堆栈；兼容历史文件，保留对话日志、本机访问限制及脱敏。

## Approaches

采用读取层聚合：读取项目 `logs` 目录现有的 `generation.log`、模型请求/响应、API 请求/响应和错误文件，按 `job_id` 转为现有运行事件。相比仅为未来任务新增日志写入，此方案能立即展示失败任务；相比单独建设页面，复用现有筛选与时间线。

生成任务以任务编号作为 `runId`，行程编号作为 `sessionId`，增加 `source=generation`、`jobId` 和 `planId`。仅纳入顶层带任务编号的结构化事件，不从嵌套 API 响应推断归属。阶段文本日志补充开始、检查点、恢复和终态；错误详情保留结构化堆栈。

读取固定文件名与 5 个轮转备份，每组最多读取最新 8 MiB；容忍损坏或正在写入的记录，截断时提示。忽略符号链接，不读取项目外文件，不写回历史日志，不访问数据库或重新运行任务。

页面增加任务编号筛选、生成阶段名称和错误识别，生成界面提供任务日志链接。继续使用原有刷新按钮，不增加轮询、依赖、导出或日志持久化系统。

日志查询响应不再回写 API 诊断文件，避免每次查看完整日志都复制相同内容并挤掉历史地图记录。

用户补充要求：API 详情明确区分请求参数与响应内容，模型详情明确区分 Prompt 与输出。响应通过现有 `call_id` 或 `requestId` 展示对应请求；保留工具调用、模型配置和原始日志 JSON，不补写缺失请求。
