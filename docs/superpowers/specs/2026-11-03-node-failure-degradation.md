# 生成节点失败降级策略

状态：策略设计，尚未实现。适用于 planning_graph 及后台 generation_jobs。

## 通用规则

- 输入校验失败不重试；网络、超时及模型输出错误才允许有限重试。模型最多三次总调用（包含首次），外部查询最多两次；已有节点内重试时不再套一层节点重试。
- 重试以最小单元进行：一个地点或一条路线失败，不重跑整个批次。服务限流或鉴权失败停止同类批量请求，不继续消耗所有地点的调用。
- 节点操作副本，成功或降级后一次性提交节点结果；异常不允许留下半修改状态。断点保存成功结果和降级原因，恢复时不重复已完成的外部调用。
- 跳过必须保证下游所需字段有效。不能伪造地点、坐标、价格、车次或审核通过结果。
- 所有降级写入 planning.generation_issues：节点、错误摘要、重试次数、采用的替代处理、受影响地点或路段及用户下一步操作；详情留服务器日志，不向页面暴露密钥。
- 有可用结果且审核完成：完成并展示降级风险；缺少必需输入：needs_input；内部状态损坏或保存失败：failed。降级不等于行程已确认。

## 节点策略

| 节点 | 重试耗尽后的处理 | 是否继续 |
|---|---|---|
| coordinator | 日期、交通选择、动作参数无效时返回明确输入问题；禁止跳过校验 | needs_input；程序异常 failed |
| transport_agent | 保留已有有效候选；允许沿用项目现有未知价格标记，不能编造班次 | 有有效选择可继续，否则 needs_input |
| guide_agent（文字/OCR） | OCR 失败优先使用本次用户明确提供的校正文字；不能静默使用另一份旧攻略 | 无可用文字则 needs_input |
| generate_guide / activity_agent | 提取失败时复用同一攻略版本对应的已保存地点；若没有则要求手动添加地点。不得从不相关旧攻略复用 | 有对应地点继续，否则 needs_input |
| hotel_agent | 搜索失败保留当前已确认酒店；无酒店时保留住宿待确认问题，不自动生成具体酒店 | 可生成草稿，但禁止假设住宿位置和酒店接驳已可靠 |
| search_places / place_agent | 单点失败保留地点、原文和错误，继续其他点；已有可靠坐标复用。无坐标点不送路线计算 | 部分可定位则继续；全部游玩点不可定位则 needs_input |
| default_choices | 自动选择失败保留已有有效选择；不把随机候选视为已确认酒店 | 按酒店策略继续 |
| prepare_draft | 可排地点为空时直接返回定位待处理信息，不调用排序模型；非法日期、重复 ID 等输入问题不能跳过 | needs_input；内部结构异常 failed |
| itinerary_agent | 修订失败保留上一份完整提案；首次排序失败用服务端规则生成草稿：遵守合法指定 day，其他地点按原输入顺序均分到旅行日，每个可排地点恰好一次。记录无法满足的约束，不向用户暂存区丢点 | 继续路线和审核；规则草稿不保证时间可行 |
| route_agent | 单条路线逐模式处理；查询抛异常与 success=false 同样处理。无可靠路线时沿用现有 provisional_estimate 草稿估计，清除旧线路和票价并记录风险 | 继续排程和审核；估计不能标为地图实测 |
| schedule_agent | 无法完成排程时保留上一份完整且输入版本一致的排程；没有则保留顺序草稿，不输出新编造的时间 | 停止自动修订，展示待排程结果；不可确认 |
| audit_agent | 审核失败不得当作通过；保留草稿，标记审核未完成，禁止确认及基于审核结果自动修订 | 可保留待审核草稿；不可确认 |
| commit_result / checkpoint | 版本冲突时保留用户新版本；数据库错误不报完成。仅对确定可安全重试的事务整体重试 | failed，保留可恢复断点；不覆盖新数据 |

## 恢复和展示

- needs_input 需要持久化可展示的部分成果（提取地点、定位结果及问题），不能只更新 job.error 后丢弃整个工作状态。保留用户已有行程；页面提供修正位置、补充文字、重新生成入口。
- 同一输入重试从失败或待补充节点恢复。修正地点时使地点定位及后续断点失效；修改攻略使提取及后续失效；只重试排序应复用已完成定位。
- 规则排序或审核失败后的草稿应带明显状态；现有 confirmed 入口必须检查审核完成及高风险问题。

## 当前任务应走的路径

地图搜索全部失败 → 保存解析地点和定位错误 → needs_input 提示确认地点位置 → 不进入空列表排序。部分定位成功则仅安排可靠地点，并把未定位点显示为生成问题。

## 落地顺序与验收

1. 先处理空地点、排序三次失败的规则草稿，以及地图单点/单路段异常隔离。
2. 补齐 needs_input 部分成果持久化、风险展示、禁止确认未审核草稿与断点失效规则。
3. 验证全部定位失败、部分定位失败、排序三次非法输出、路线接口抛异常、排程/审核失败、数据库保存失败和恢复后输入已变化等场景。

不要用统一 catch Exception 后跳过全部节点的方式实现；每个降级结果必须满足上述数据和状态约束。
