# 审核父子 Agent 预算与恢复设计

## 目标

父子 Agent 独立控制工具调用，失败后由模型根据错误选择修正参数、换工具或交付结果。在超时、步骤上限和预算耗尽时保留经过工具验证的成果。审核结构化决策使用 OpenAI Chat Completions 的严格 JSON Schema。

## 已确认的预算口径

- 每次子任务执行独立分配 8 次正常工具调用，失败后的纠错调用不计入这 8 次。
- 首次失败后允许模型最多再作 3 次纠错调用，每次先收到工具名称、实际参数、错误类型和原因。不会程序性重复发送相同请求。
- 同一次调用首次失败后最多纠错 3 次，失败链结束后向 Agent 返回重试耗尽状态。成功重置该工具的失败计数。Agent 可以换工具、发起新操作或提交部分结果。
- 父 Agent 当前没有直接业务工具。每次派发一个子任务计作父 Agent 的一次委派工具调用，整轮有 8 次正常额度。纠错委派沿用三次免费重试，每个新执行的子任务有自己的 8 次额度。
- Workflow 的初始快照、最终试算与授权保存属于应用边界。保留其版本、权限和写入结果核实机制。

## 错误反馈与收尾

- 模型每轮收到当前剩余调用次数、失败历史和可用工具。
- 审核只读工具取消工具层自动重复请求，直接把失败结果交给 Agent。其他业务调用方继续使用原有重试逻辑。
- 工具执行失败后，下一次模型决策可以调整参数重试、调用其他工具或结束任务。父 Agent 接收子任务错误与部分成果后，可以修订任务或交付结果。
- 一批工具调用超过剩余预算时，超额项返回明确状态，保持 assistant 调用和 tool 响应一一匹配。
- 步骤和预算结束前预留一次仅提交结果的模型调用。超时或模型不可用时由应用返回已验证成果和未完成任务。
- 默认模型步骤上限为 32，另加一次只提交结果的收尾调用，使 8 次正常调用及其三次纠错都有决策空间。单次操作时限保持 60 秒。
- 子任务结果增加结构化失败记录、已验证候选、路线结果和剩余事项。失败、超时与预算耗尽不删除这些字段。
- 父 Agent 最终总结失败也返回已有任务成果。部分成果不能绕过编辑提案的版本、权限和试算校验。

## 结构化输出

- 复用现有 OpenAICompatibleClient 的 response_format，使用 type=json_schema、strict=true。
- 为意图识别、父 Agent 决策和各子 Agent 结果定义明确 Schema。对象关闭 additionalProperties，字段全部 required，可选值通过 null 表达。
- 动态任务输入统一为 goal、day、constraints，避免开放字典导致严格 Schema 无效。编辑操作复用现有业务契约并转换为提供方支持的 Schema，解析后继续业务校验。
- 原生工具调用用于执行工具。最终结果受 response_format 约束并在本地校验，不用正则截取 JSON。
- 显式处理模型拒绝、空响应、截断和 Schema 不兼容错误。提供方不支持严格输出时返回可诊断错误。

## 文件职责与验证

- review_workflow.py、review_parent.py、review_scheduler.py 处理预算归属、委派额度、重规划和部分结果传播。
- review_children.py 处理子任务循环、逐次失败反馈和最终收尾。
- 新建 review_contracts.py 集中定义审核决策 Schema 与解析规则。
- tools/review.py 让审核工具单次执行，压缩面向模型的搜索结果。
- infrastructure/llm.py、service/utils/model_client.py 检查结构化输出参数和拒绝、截断处理，保持其他调用方兼容。
- tests/test_review_reliability.py、tests/test_review_agent_workflow.py、tests/test_review_assistant_http.py 验证独立预算、参数修正、失败链耗尽、超时保留成果、严格输出和 HTTP 兼容性。复用现有 tests/test_model_client.py 验证模型传输。
- 审核 HTTP 测试验证部分成果通过真实入口到达响应，保存路径继续遵守权限和版本约束。

## 其他稳定性改进

- 区分对话结束与业务完成，避免失败说明被记录为业务成功。
- 搜索达到所需候选数量后结束，避免无界扩展查询。
- 给日志增加 Agent/任务、预算使用、失败类别和部分成果计数。
- 对“先选地点再编辑”的规则保留显式授权判断，避免用户已交由助手决定后仍重复追问。
- 用真实失败记录构造可重复回放用例，按业务目标完成率、恢复成功率和延迟评估。

## 范围

本次围绕路线审核页父子 Agent。普通聊天图和行程生成工作流拥有独立执行方式，需另外验证后再推广同样规则。

## 交付与后续优化分析

已实现独立预算、模型参与的失败恢复、额外收尾调用、经过工具验证的成果保留、OpenAI 严格 Schema、部分结果 HTTP 响应和错误运行状态。审核搜索工具不再隐藏自动重试，也不向模型重复发送 raw_places。公开答复模型发生上下文错误时使用已有事实兜底。

后续优化按影响排序如下。

1. 整轮截止时间。独立预算及免费纠错提高可恢复性，也提高了最坏时长。增加整轮截止时间时，需取消仍在运行的只读请求、交付当前成果，并继续独立处理写入结果未知状态。
2. 模型与提供方验收。对当前三个模型分别验证原生工具调用、严格 json_schema、拒绝及截断行为。OpenAI 兼容地址不代表提供方支持全部严格 Schema 能力。当前实现遇到不兼容会明确失败，尚未进行真实提供方验收。
3. 真实任务回放评测。将这次失败轨迹和地点选择、多日修改等请求固定为离线回放，区分用户主动澄清、部分完成、工具故障和最终目标达成，衡量恢复成功率及延迟。
4. 上下文与证据管理。已去掉重复原始 POI，仍可按请求去重行程快照与重复路线，并将历史证据存为引用，减少父子消息复制。
5. 授权与任务依赖。进一步验证用户已授权助手自行选择时的直达编辑路径，审核新方案应明确依赖候选与拟定操作，避免仅审核旧路线就结束。

HTTP 新增 partial 状态及 progress 字段，progress 保留 places、routes、contexts、remaining 和 failures。最终提交失败也携带此前成果。部分结果使用既有候选卡片和问题展示，断点仍可重试。运行日志将 partial 记作 failed，避免把对话结束计为业务完成。
